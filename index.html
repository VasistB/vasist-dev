iPlay Music Player

View on Google Play

Queue & Shuffle Engine

Designed a stateful playback queue that separates display order from playback order, allowing shuffle, filtering, queue restoration, and playback history to operate without mutating the underlying library.

Playback Architecture

Built the playback layer around Media3 MediaController + MediaSession, keeping UI state, playback state, and the active queue synchronized across foreground and background playback.

Local Library

Built a Realm-backed local music index over MediaStore, enabling reactive library updates and offline-first browsing of large local collections, keeping all UI work safely off the main thread.

Engineering Results

  • Playback continues independently of UI lifecycle
  • Queue survives configuration/process restoration
  • Shuffle preserves current playback position
  • Local library remains available offline
  • MediaStore processed off the main thread

Engineering Philosophy

State is Explicit

UI should render state, not own business logic. I build with unidirectional data flow (UDF) to ensure predictable behavior.

Offline First

Local data should remain useful when the network disappears. Persistence is a first-class citizen in my architectures.

Lifecycle Aware

Long-running work should not depend on an Activity or Composable. I leverage WorkManager and Service-based solutions.

Measure Before Optimizing

Performance decisions come from profiling, not assumptions. I use Benchmark and Profiler tools to validate changes.

Failure is a State

Loading, empty, partial and error states are part of the core architecture, not an afterthought.
